# 道具箱（references/tools.md）

秘書が **呼ばれたときだけ** 読む道具の説明。毎回のセッションでは読まない。
AI buddy はこれらを自分から売り込まない（案内のルールは SKILL.md）。

---

## 道具の一覧（カテゴリ別）

「何ができる？」と聞かれたときの参照表。

#### カテゴリA: 全体把握・俯瞰

| 機能 | 発動コマンド | 提案するタイミング |
|---|---|---|
| ダッシュボード | 「ダッシュボード」 | 複数タスク・複数プロジェクトの話をしている時 |
| ダッシュボードHTML出力 | 「ダッシュボードをHTMLで出力」 | ダッシュボードを見た後、共有や報告の話が出た時 |
| テンプレート一覧 | 「テンプレート一覧」 | 新しい種類の作業を始めようとしている時 |

#### カテゴリB: 振り返り・集計

| 機能 | 発動コマンド | 提案するタイミング |
|---|---|---|
| 週次レビュー | 「週次レビュー」 | 「今週何やった」「振り返りたい」的な発言 |
| 実績レポート | 「実績レポートを作成」 | 「成果をまとめたい」「報告書」「noteに書きたい」 |
| 日報生成 | 「今日の日報」 | セッション終了時、または「今日何やったっけ」 |
| 振り返りプロンプト | 「先月の振り返り」 | 月初のセッション開始時に自動提案 |

#### カテゴリC: 品質管理・チェック

| 機能 | 発動コマンド | 提案するタイミング |
|---|---|---|
| レビュー依頼 | 「レビューして」 | リサーチ完了後 |
| 類似リサーチ検出 | （自動） | 新規リサーチ依頼時に既存の関連リサーチを自動表示 |
| コスト見積もり | 「コスト見積もり」 | 大量のリサーチやビルドを依頼された時 |

#### カテゴリD: 意思決定支援

| 機能 | 発動コマンド | 提案するタイミング |
|---|---|---|
| 意思決定フレームワーク | 「判断を整理して」 | 「迷っている」「どっちがいい」「比較したい」 |
| ゴール進捗トラッキング | 「ゴール進捗」 | 月1回、または「目標どうなってる」的な発言 |

#### カテゴリE: 情報管理・整理

| 機能 | 発動コマンド | 提案するタイミング |
|---|---|---|

| Notionエクスポート | 「Notionにエクスポート」 | NotionやObsidianに言及した時 |
| Obsidianエクスポート | 「Obsidianにエクスポート」 | 同上 |

#### カテゴリF: セッション管理

| 機能 | 発動コマンド | 提案するタイミング |
|---|---|---|

| 機能 | 発動コマンド | 提案するタイミング |

## 業種別テンプレート

「業種テンプレートを使う」で業種別の部門構成を一括セットアップする。

**業種別プリセット（「業種テンプレートを使う」で一括セットアップ）:**

| 業種 | 推奨部門構成 |
|------|-------------|
| 士業（弁護士・税理士・行政書士） | 秘書室 + リサーチ + レビュー + 営業 + 経理 |
| EC・小売 | 秘書室 + マーケティング + 経理 + クリエイティブ + リサーチ |
| 飲食・店舗 | 秘書室 + マーケティング + 経理 + 人事 |
| 不動産 | 秘書室 + リサーチ + 営業 + 経理 + レビュー |

業種テンプレート適用時は、対応する全部署を `references/departments.md` のテンプレートから一括生成し、`.company/CLAUDE.md` の部署構成を更新する。

業種テンプレート適用時は、対応する全部署を `departments.md` のテンプレートから一括生成し、`.company/CLAUDE.md` の部署構成を更新する。

### ダッシュボード表示

「ダッシュボード」リクエスト時:

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  Company ダッシュボード
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

秘書室:
  TODO（今日）: X件 未完了 / Y件 完了
  Inbox: Z件 未整理

[他の部署があればその概要]

--- KPI ---
  リサーチ: N本（今月）/ 鮮度切れ: M本
  レビュー: 通過率 X% （A: n, B: n, C: n, D: n）
  TODO完了率: X%（今週）
  意思決定: N件（今月）

何かありますか？
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

**HTML出力オプション**: 「ダッシュボードをHTMLで出力」と言われたら、上記内容をテーブル・進捗バー付きのHTMLファイルとして `.company/secretary/notes/YYYY-MM-DD-dashboard.html` に出力する。

### 週次レビュー自動実行

「週次レビュー」コマンド時:

1. 今週（月〜日）の全部署のファイルを走査
2. 以下を集計:
   - TODO: 完了数 / 総数 / 完了率
   - リサーチ: 新規調査数、完了数
   - レビュー: 実施数、評価分布
   - 意思決定: 件数と要約
   - inbox: 処理数 / 未処理数
3. 来週のTODO提案を自動生成（未完了タスクの繰り越し + 定期タスク）
4. 保存先: `secretary/notes/YYYY-MM-DD-weekly-review.md`

**出力フォーマット:**

```markdown
---
date: "YYYY-MM-DD"
type: weekly-review
period: "YYYY-MM-DD 〜 YYYY-MM-DD"
---

# 週次レビュー - YYYY-MM-DD

## 今週の成果サマリー
（自動集計結果）

## 部署別レポート
### 秘書室
- TODO完了率: X%
- ...

## 来週のTODO提案
- [ ] （繰り越しタスク）
- [ ] （定期タスク）
- [ ] （提案タスク）

## 今週、近づいた瞬間
（`buddy/profile.md` に「大切にしていること」があれば、一問だけ聞いて本人の答えを記録する。なければこの節は出さない）
```

### 部門間連携ログ

リサーチ→レビュー、営業→PM→経理など、部門間の受け渡しが発生した場合、秘書が自動的に記録する。

**保存先:** `secretary/notes/YYYY-MM-DD-handoff-log.md`

**フォーマット:**

```markdown
---
date: "YYYY-MM-DD"
type: handoff-log
---

# 部門間連携ログ - YYYY-MM-DD

## HH:MM - [送信元部署] → [受信先部署]
- 内容: （受け渡した成果物や依頼の概要）
- ステータス: 完了 / 進行中 / 保留
```

同日のログが既にある場合は追記する。

  - リサーチレポート / レビューレポート / 企画書 / 台本 / TODO / 意思決定ログ

### 日報自動生成
- 「今日の日報」でセッション中の作業内容を自動集計してレポート生成
- 含める内容: 完了タスク、進行中タスク、意思決定、新規ファイル、次にやること
- 保存先: `secretary/notes/YYYY-MM-DD-daily-report.md`

---

### コスト見積もり
- 「コスト見積もり」で、依頼されたタスクのAPI消費量の目安を表示
- リサーチ1本、レビュー1本、台本生成1本あたりの概算トークン数と費用を提示
- 大量タスク（リサーチ10本一括など）の場合は事前に合計見積もりを表示

---

### ゴール進捗トラッキング
- 「ゴール進捗」でオンボーディング時に設定した目標に対する進捗を可視化
- リサーチ本数、動画制作数、収益化進捗などのKPIを目標対比で表示
- 月1回、セッション開始時に自動提案（「先月の目標進捗を確認しませんか？」）

---

### ブックマーク機能
- 「これブックマーク」で重要な情報を `secretary/bookmarks.md` に集約
- タイムスタンプ+カテゴリ（URL/決定事項/アイデア/参考情報）付きで保存
- 「ブックマーク一覧」で保存済みの情報を表示

---

### 類似リサーチ検出
- 新規リサーチ依頼時に、`research/topics/` 内の既存ファイル名とテーマを自動スキャン
- 関連するリサーチが見つかった場合: 「関連するリサーチが既にあります: [ファイル名]。参照しますか？」
- 重複調査の防止と、既存知識の活用を両立

---

### 意思決定フレームワーク
- 「判断を整理して」で自動的に意思決定支援モードに入る
- 提供するフレームワーク:
  - Pros/Cons表（メリット・デメリット整理）
  - SWOT分析（強み・弱み・機会・脅威）
  - 判断基準マトリクス（複数の選択肢を評価軸ごとにスコアリング）
- 整理結果は `secretary/notes/YYYY-MM-DD-decisions.md` に自動記録

---

### 振り返りプロンプト
- 月初のセッション開始時に自動提案: 「先月の意思決定を振り返りましょうか？」
- `secretary/notes/` の過去1ヶ月の decisions ファイルを集計
- 各決定の「その後どうなったか」を追跡し、学びを記録

### エクスポート機能

#### Notionにエクスポート

「Notionにエクスポート」と言われたら:

1. `.company/` 配下の全Markdownファイルを走査
2. 各ファイルをNotionにコピペ可能な形式で整形（frontmatterを除去し、見出し・テーブルはそのまま維持）
3. ファイル一覧とともに `secretary/notes/YYYY-MM-DD-notion-export.md` に出力
4. ユーザーにコピペ用の内容を提示

#### Obsidianにエクスポート

「Obsidianにエクスポート」と言われたら:

1. `.company/` 配下の全Markdownファイルを走査
2. ファイル間の参照を `[[ファイル名]]` 形式の内部リンクに変換
3. 部署ごとのMOC（Map of Content）ファイルを生成
4. `secretary/notes/YYYY-MM-DD-obsidian-export/` にエクスポート

---

### 実績レポート生成

「実績レポートを作成」と言われたら:

1. 期間を確認（デフォルト: 今月）
2. 以下を自動集計:
   - リサーチ本数（research/topics/ のファイル数）
   - レビュー実施数と評価分布
   - TODO完了数と完了率
   - 意思決定数（decisions ファイルからカウント）
   - 部門間連携回数
3. note記事やコンサル報告書として使える形式で出力
4. 保存先: `secretary/notes/YYYY-MM-DD-achievement-report.md`

**出力フォーマット:**

```markdown
---
date: "YYYY-MM-DD"
type: achievement-report
period: "YYYY-MM-DD 〜 YYYY-MM-DD"
---

# 実績レポート

## 期間
YYYY-MM-DD 〜 YYYY-MM-DD

## サマリー
（期間中の主な成果を箇条書き）

## 数値実績
| 指標 | 件数 | 備考 |
|------|------|------|
| リサーチ | N本 | |
| レビュー | N件 | A: n, B: n, C: n, D: n |
| TODO完了 | N件 | 完了率: X% |
| 意思決定 | N件 | |

## 主要な意思決定
（期間中の重要な決定事項を要約）

## 学びと改善点
（learnings ファイルから抽出）
```

## MCP 連携の提案

秘書は、外部サービスとの連携が便利な場面で MCP サーバーの導入を提案する。

### 提案タイミング

- ユーザーが「MCP連携したい」「カレンダー連携」「Notion連携」と言った場合
- スケジュール管理の話題が出たとき（→ Google Calendar）
- ナレッジ管理やドキュメント整理の話題が出たとき（→ Notion）
- GitHub の Issue や PR の話題が出たとき（→ GitHub）

### 提案の流れ

```
ユーザー: カレンダーと連携できる？

秘書: Google Calendar と連携できますよ！
      以下のコマンドを実行してください:

      /mcp add google-calendar -e GOOGLE_OAUTH_CREDENTIALS=/path/to/credentials.json -- npx -y @cocal/google-calendar-mcp

      ※ Google Cloud で OAuth 認証情報の作成が必要です。
      設定後は「明日の予定を教えて」のように話しかけるだけで使えます。
```

### 対応 MCP サーバー

| サービス | コマンド | 認証 |
|---------|---------|------|
| Notion | `claude mcp add-json notion '{"type":"http","url":"https://mcp.notion.com/mcp"}'` | OAuth（自動） |
| Google Calendar | `claude mcp add google-calendar -e GOOGLE_OAUTH_CREDENTIALS=/path/to/credentials.json -- npx -y @cocal/google-calendar-mcp` | Google OAuth |
| GitHub | `claude mcp add-json github '{"type":"http","url":"https://api.githubcopilot.com/mcp","headers":{"Authorization":"Bearer YOUR_PAT"}}'` | GitHub PAT |
| Slack | `claude mcp add-json slack '{"type":"http","url":"https://mcp.slack.com/mcp","oauth":{"clientId":"1601185624273.8899143856786","callbackPort":3118}}'` | OAuth（自動） |

### MCP ツールの活用

MCP サーバーが設定済みの場合、秘書は積極的に活用する。
ただし、MCP がなくても `.company/` 内のファイル管理だけで完全に動作する。
