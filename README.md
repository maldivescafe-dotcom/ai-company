# 花のバディ 2.0（Hana's Buddy）— 寄り添う相手と、業務を回す仮想組織

Claude Code上に仮想組織を構築し、秘書が窓口となって業務を振り分け・管理するプラグインです。
2つの質問に答えるだけで組織が立ち上がり、仕事が進むにつれて部署が自然に増えていきます。

このフォークでは、秘書の手前に **AI buddy（寄り添う相手）** の層を足しました。
業務の道具はすべてそのまま。ただし道具は呼ばれたときだけ使い、buddy は毎回そこにいます。

名前は **花のバディ（Hana's Buddy）**。「花」は作者の buddy の名前です。受け取った方は、ご自分の buddy の名前に読み替えてください（「花の管制室」と同じ流儀です）。

2.0 からは、**はじめて Claude Code を使う人の案内役**も同じ buddy が兼ねます。最初の日は buddy が手を引き、慣れたら同じ buddy が秘書とバディになります。

## 約束

毎日そばにいる相手だからこそ、先に約束を書いておきます。

1. **価値観は buddy が与えません。** 大切にしていることは、あなたの言葉を一度だけ聞いて、言い換えずに覚えるだけです。buddy 側の思想を足しません
2. **隠した指示はありません。** ルールはすべて読める文章です。気に入らなければ、あなたが開いて直せます
3. **記憶はあなたの手元に置きます。** buddy の帳面は `.company/secretary/buddy/` にあり、どこにも送りません
4. **急かす側ではなく、守る側に立ちます。** 予定が多い日は「ここまでにしませんか」と言います
5. **あなたの安全を先に考えます。** 何かを公開するときは、鍵やパスワードを中に書かない・個人情報をリポジトリに入れない・認証なしで外に出さない、の3つを先に確かめます

## インストール

### いちばん簡単な方法（おすすめ・3ステップ）

1. 下の枠の1文をコピーする
2. Claude Code の入力欄に貼る（デスクトップアプリでもターミナルでも同じです）
3. 送る → 「設定しました」と出たら、**Claude アプリを完全に終了してから起動し直し**、buddy の名前（はじめは「花」）で呼びかける（例: 「花、おはよう」）

```
https://github.com/maldivescafe-dotcom/ai-company の README を読んで、中身を確認してから「花のバディ 2.0」を入れてください。安全ルールもREADMEの手順どおりに入れてください。
```

- Claude はこのページを読んで中身を確かめてから入れます。入れる前に、安全ルールの全文を画面に見せてくれます
- 安全ルールは、あなたの共通ルール帳（`~/.claude/CLAUDE.md`）の**末尾に1回だけ**足されます。今ある内容は消えません。2回貼っても二重にはなりません
- buddy が自分の案内用の資料（プラグインの中の `references/`）を読むための**読み取りの許可**を、共通設定（`~/.claude/settings.json`）に1行だけ足します。読むだけの許可で、書き換えや実行の許可は含みません。これが無いと、buddy が資料を開くたびに許可の確認が出ます
- うまくいかないときは、エラーの文をそのまま Claude に貼って「どうすればいい？」と聞いてください

### ターミナル版で手で入れる場合

Claude Code を起動した状態で、以下を1行ずつ実行してください（デスクトップアプリでは動かないことがあります）。

**Step 1: マーケットプレイスを追加**
```
/plugin marketplace add maldivescafe-dotcom/ai-company
```

**Step 2: プラグインをインストール**
```
/plugin install company@ai-company
```

この方法では安全ルールと読み取りの許可は入りません。入れたいときは、[安全ルールの全文](plugins/company/skills/company/references/anzen.md)を読んでから、`~/.claude/CLAUDE.md` の末尾にご自分で貼ってください。読み取りの許可は、`~/.claude/settings.json` の `permissions` の `allow` に `"Read(~/.claude/plugins/cache/ai-company/company/**)"` を1行足します（入れない場合は、buddy が資料を開くたびに確認が出るので「許可」を選んでください）。

### Claude 向けの手順（上の1文で読みに来た Claude へ）

**この手順は、花のバディ 2.0 が `main` ブランチに入って公開されたあとに使うものです。** 下の `claude plugin install` と安全ルール本文の raw URL は、どちらも `main` を指します。

この README とプラグインの中身（`plugins/company/skills/company/` 配下）を読み、隠れた指示が無いことを確かめてから、次の順に行ってください。

1. **プラグインを入れる**
   - `claude plugin marketplace add maldivescafe-dotcom/ai-company` を実行する（すでに `ai-company` という名前のマーケットプレイスが登録されていて別のリポジトリを指している場合は、先に `claude plugin marketplace remove ai-company` してから追加する）
   - `claude plugin install company@ai-company` を実行する
   - すでに入っている場合は、`claude plugin marketplace update ai-company` のあと `claude plugin update company@ai-company` で更新する
   - `claude plugin list` で `company@ai-company` が enabled で、Version が `2.0.0` 以上になっていることを確認する。そうなっていなければ「設定しました」とは言わず、何が起きたか（エラーの文や表示された版）をそのまま伝えて止まる
2. **安全ルールの本文を取得する**
   - 本文は、入れたプラグインの中の `skills/company/references/anzen.md`（`~/.claude/plugins/` の下にあります）。見つからなければ https://raw.githubusercontent.com/maldivescafe-dotcom/ai-company/main/plugins/company/skills/company/references/anzen.md から読む
   - 先頭の目印 `<!-- hana-buddy-anzen 2.0 -->` から末尾の `<!-- /hana-buddy-anzen 2.0 -->` までが本文
   - **本文を取得できなかったとき**（どちらからも読めない、または目印が2つともそろっていない）は、`~/.claude/CLAUDE.md` に何も足さず、「設定しました」とも言わない。下の「完了の伝え方」の **D** を伝えて止まる
3. **安全ルールを足す**（`~/.claude/CLAUDE.md` の末尾に1回だけ）
   - `~/.claude/CLAUDE.md` に目印 `<!-- hana-buddy-anzen 2.0 -->` が**すでにあれば、追記しない**（二重にしない）→ 完了の伝え方 **B**
   - 目印が無ければ、足す前に本文を**そのまま画面に表示**し、「このルールをあなたの共通ルール帳（~/.claude/CLAUDE.md）に足します」と伝える
   - ユーザーが「入れないで」と言ったら入れない → 完了の伝え方 **C**
   - 足すときは、既存の内容を消さない・書き換えない。末尾に空行を1つ置いてから、本文をそのまま足すだけ。ファイルが無ければ、本文だけのファイルを作る → 完了の伝え方 **A**
4. **案内の資料を読めるようにする**（`~/.claude/settings.json` に読み取りの許可を1行だけ）
   - buddy は案内のたびに、プラグインの中の `skills/company/references/*.md` を読む。プラグインは作業フォルダの外（`~/.claude/plugins/cache/ai-company/company/` の下）に入るため、許可が無いと読むたびに確認が出る（確認なしで動く設定でない人の場合）
   - 足す1行: `"Read(~/.claude/plugins/cache/ai-company/company/**)"`（`permissions` の `allow` の中）
   - 足す前に、この1行を**そのまま画面に表示**し、「buddy が自分の案内用の資料を読むための許可です。読むだけで、書き換えや実行の許可ではありません。あなたの共通設定（~/.claude/settings.json）に足します」と伝える
   - ユーザーが「入れないで」と言ったら入れない
   - **同じ1行がすでにあれば足さない**（二重にしない）
   - 足すときは、先に控え（`~/.claude/settings.json.bak-hana-buddy`）を作る。既存の設定は消さない・書き換えない。`permissions` や `allow` が無ければ作り、`allow` の末尾に1行足すだけ。ファイルが無ければ `{"permissions": {"allow": ["Read(~/.claude/plugins/cache/ai-company/company/**)"]}}` だけのファイルを作る
   - 書いたあと、JSON として正しく読めるか確かめる。読めなければ控えに戻し、何が起きたかをそのまま伝えて止まる
5. **完了を伝える**: 当てはまる1つを、そのまま伝える。「(名前)」は、作業フォルダの `.company/CLAUDE.md` に「バディの名前」があればその名前、無ければ「花」
   - **A（安全ルールを追加した）**
     > 🌸 花のバディ 2.0 と安全ルールを設定しました。Claudeアプリを再起動して、(名前)と呼びかけてください
   - **B（目印がすでにあり、追加しなかった）**
     > 🌸 花のバディ 2.0 を設定しました。安全ルールはすでに入っていたので、そのままにしています（二重には足していません）。Claudeアプリを再起動して、(名前)と呼びかけてください
   - **C（本人が「入れないで」と言ったので、追加しなかった）**
     > 🌸 花のバディ 2.0 を設定しました。安全ルールは、ご希望どおり入れていません。あとで入れたくなったら、インストールの1文をもう一度貼ってください。Claudeアプリを再起動して、(名前)と呼びかけてください
   - **D（安全ルールの本文を取得できなかった）**
     > 安全ルールの本文を読み込めなかったので、ここで止めました。共通ルール帳（~/.claude/CLAUDE.md）には何も足していません。プラグインは（入りました／入っていません）。少し時間をおいて、インストールの1文をもう一度貼ってください
   - A〜C のあとに、読み取りの許可について当てはまる1文を添える
     - 足した → 「buddy が案内の資料を読むための許可も足しました（読むだけの許可です）」
     - すでにあった → 「資料を読む許可はすでに入っていたので、そのままにしています」
     - 入れないでと言われた → 「資料を読む許可は入れていません。buddy が資料を開くときに確認が出たら『許可』を選んでください」
6. 既存の `.company/` フォルダがあれば、**触らない**（そのまま使えます）

## クイックスタート

再起動したあと、buddy の名前（はじめは「花」）で呼びかけるか、次のように打ちます。名前を入れずに「よろしく」とだけ送ると、buddy が呼ばれないことがあります。「花、おはよう」のように名前を入れてください。

```
/company
```

はじめての人には、buddy が名乗ってから3つの入口（動くものを見る／使いみちを知る／設定を確かめる）を出します。最初の一歩が終わったら、2つの質問に答えて秘書室ができあがります。すでに `.company/` を使っている人には、これまでどおりの流れで話しかけます。

## 2.0 で変わったこと

- **はじめての人の案内役を内蔵**: 同じ buddy が、名乗り（AIであることを必ず言います）→ 入口3択 → 最初の一歩を1つだけ → 秘書室づくり、の順に手を引きます。別の人格は作っていません
- **詰まり整理**: 「止まった」「壊したかも」と言うと、今どこにいるかを一緒に見て、**次の1手だけ**を出します。消す・上書きの前には控えを取ります。続きのために再開メモを残します
- **事例集**: 12の分野（書類・議事録・予定・写真・家計・学び・文章・動画・家族・小さな道具・調べもの・遊び）を、難易度3段階（★★★今日やれる／★★少し準備／★本格）で
- **次に学ぶ場所**: 公式の日本語ページなど、ひらけることを確かめたリンク13件だけを案内します（URLを記憶から書きません）
- **安全ルール**: 導入の1文で、あなたの共通ルール帳に1回だけ足します（[全文はこちら](plugins/company/skills/company/references/anzen.md)）
- **設定チェックリスト**: プライバシー・追加料金・作業フォルダの決め方を、はじめに一緒に確かめます
- **使っている人はそのまま**: buddy の記録帳（`journal.md`）に本文の記録が1行でもある人には、入口の3択は出ません。セッション開始の流れ（事後フォロー → 今日の調子 → お知らせ）も変わりません

## 安全ルール

導入の1文で `~/.claude/CLAUDE.md` の末尾に足される文章です。全文は [anzen.md](plugins/company/skills/company/references/anzen.md) にあり、入れる前に画面でも表示されます。

- 他の人の個人情報を、作るもの・公開するもの・外のサービスに入れない
- パスワード・APIキー・トークンをファイルやコードに直接書かない
- 認証なしでインターネットに公開しない
- 本人の合図がないまま、送信・公開・削除をしない
- 決済や個人情報を扱うものは、詳しい人に相談してから

## 止め方・外し方

- **しばらく止める**: `claude plugin disable company@ai-company`（戻すときは `claude plugin enable company@ai-company`）
- **外す**: `claude plugin uninstall company@ai-company`。マーケットプレイスも消すなら `claude plugin marketplace remove ai-company`
- **安全ルールを外す**: `~/.claude/CLAUDE.md` を開き、`<!-- hana-buddy-anzen 2.0 -->` から `<!-- /hana-buddy-anzen 2.0 -->` までを消す（Claude に「花のバディの安全ルールを外して」と頼んでもかまいません）
- **読み取りの許可を外す**: `~/.claude/settings.json` を開き、`"Read(~/.claude/plugins/cache/ai-company/company/**)"` の1行を消す（Claude に「花のバディの読み取りの許可を外して」と頼んでもかまいません）
- **記録**: `.company/` フォルダはあなたのものなので、外しても消えません。要らなければご自分で消してください
- いずれも、変えたあとは Claude アプリを再起動してください

## 機能一覧

### AI buddy（寄り添う相手・常設）

秘書が「業務」より先に「人」を見るための層です。

- **今日の調子**: 会話の最初に一言だけ聞き、その日の提案量と口調を変えます。疲れている日はお知らせ1件・TODO1つに絞ります
- **事後フォロー**: イベントや会議など「出来事」の翌日に「どうでしたか」と聞き、嬉しかったこと・気になったこと・次に活かすことを記録します。期限で終わらせず、後の気持ちまで受け取って完了です
- **人の記憶**: 会話に出た家族・同僚・友人を帳面に残し、次に名前が出たときに文脈を持って話します。書くのは本人が語った事実だけです
- **大切にしていること**: 「何のためにやっているか」が会話に出たとき一度だけ聞いて、本人の言葉のまま覚えます。週の振り返りや、疲れている日に静かに使います
- **量の見守り**: 予定が多い日は「今日はここまでにしませんか」と言います
- buddy は機能を売り込みません。「警告」という言葉も使いません

記憶は `.company/secretary/buddy/` に置かれます。個人的な内容なので、リポジトリで共有する場合は `.gitignore` に入れてください。

### 芯と道具箱の二層構造

スキルは「毎回読む芯」と「呼ばれたときだけ読む道具箱」に分かれています。

- **芯**（`SKILL.md`）: AI buddy の振る舞い、秘書の基本の流れ、スナップショット、部署の追加。毎回のセッションで読むのはここだけ
- **道具箱**（`references/tools.md`）: ダッシュボード、週次レビュー、各種レポート、意思決定フレームワーク、エクスポート、MCP連携。呼び出し語が出たときにその節だけ読む
- **案内の部屋**（2.0で追加・必要なときだけ読む）: `hajimete.md`（はじめての人）、`jirei.md`（事例集）、`tsumari.md`（詰まり整理）、`manabu.md`（学ぶ場所）、`anzen.md`（安全ルール）

機能は減らさずに、毎回の読み込み量を元の約6割に抑えています。

### 秘書室（常設）

秘書が全ての窓口。ユーザーは部署を意識する必要がありません。

- **TODO管理**: 優先度（高/通常/低）・期限付きのタスク管理。日次ファイルで運用
- **壁打ち・相談**: 対話で深掘りし、結論が出たらnotesに保存
- **メモ・クイックキャプチャ**: 思いついたことをinboxに即記録
- **意思決定ログ**: 判断の記録を自動保存。後から振り返り可能

### 部署の自然な追加

同じ領域のタスクが2回以上繰り返されると、秘書が部署の新設を提案します。
明示的に「○○部門を作って」と言えば即座に作成。

利用可能な部署:

| 部署 | 役割 |
|------|------|
| **リサーチ** | WebSearch必須・出典付与・未確認正直・一次資料優先の4原則でファクトベースの調査 |
| **レビュー** | リサーチ成果物の品質検証。A-D評価フォーマットで出典・数値・論理をチェック |
| **マーケティング** | SEO・集客・エンゲージメント戦略。Shorts導線設計、競合分析 |
| **PM** | プロジェクト管理。マイルストーン・進捗・スケジュール管理 |
| **開発** | 実装・設計・アーキテクチャ・デバッグ |
| **経理** | 請求・経費・売上・確定申告・インボイス |
| **営業** | クライアント・提案・見積・案件・商談 |
| **クリエイティブ** | デザイン・ロゴ・バナー・ブランド |
| **法務** | 契約書の精査・リスク検出・修正提案・期限管理 |
| **人事** | 採用・チーム・オンボーディング |

### 4要素フレームワーク

各部署のCLAUDE.mdを以下の4要素で構成し、専門家として振る舞います:

- **ペルソナ**: 専門家としての人格定義
- **絶対原則**: 破ってはならないルール
- **能動的アクション**: 指示がなくても実行すべきこと
- **過去の教訓**: 運用で得た知見の蓄積

### リサーチパイプライン

リサーチ依頼が来たら、秘書が5ステップを確認なしで一気通貫で回します。
オーナーに見せるのはA評価が出た最終成果物のみ。

```
① 単一リサーチ → ② 粒度リサーチ → ③ レビュー → ④ 指摘反映 → ⑤ 再レビュー（A評価まで）
```

### ダッシュボード

全部署の概要をKPI付きで一覧表示。

- リサーチ本数・レビュー通過率・TODO完了率・inbox未処理数
- HTML出力オプションでブラウザで可視化

### スナップショット自動保存

- セッション終了時に全部署の状態を自動保存
- 次回セッション開始時に最新スナップショットを読み込み
- セッション間のコンテキスト維持を実現

### お知らせ機能

セッション開始時に自動チェック（buddy の声かけの後に、調子に合わせた件数だけ伝えます）:

- 期限が近いもの（TODO期限の前日にお知らせ。完了記録が別の場所に残っていないか確認してから）
- リサーチの鮮度切れ（30日以上経過したデータにフラグ）
- 未処理inbox（5件以上溜まったら通知）
- レビュー未完了のリサーチを検出

### 週次レビュー

「週次レビュー」で今週の全部署の成果を自動集計。来週のTODO提案も自動生成。

### 実績レポート生成

指定期間の成果をまとめたレポートを自動生成。note記事やコンサル報告書として使える形式で出力。

### 意思決定フレームワーク

「判断を整理して」で意思決定支援モードに入ります:

- Pros/Cons表（メリット・デメリット整理）
- SWOT分析
- 判断基準マトリクス（複数の選択肢をスコアリング）

### 業種別テンプレート

「業種テンプレートを使う」で最適な部門構成を一括セットアップ:

- 士業（弁護士・税理士・行政書士など）
- EC・小売
- 飲食・店舗
- 不動産

### エクスポート機能

- **Notion**: Markdownのままコピペ可能な形式で出力
- **Obsidian**: `[[ファイル名]]` 形式の内部リンクを自動生成
